# 知己簿 · Know Your Friends 开发与公开发布流程

本流程适用于知己簿 · Know Your Friends 的维护者与外部贡献者。公开仓库为 [youdrew/know-your-friends](https://github.com/youdrew/know-your-friends)，`main` 保存已审核的公开版本。

更新日期：2026-10-09（Asia/Taipei）。

## 分支与 Pull Request

1. 从最新公开 `main` 创建范围明确的功能或修复分支。
2. 完成改动、相关测试和必要的文档更新。
3. 向 `main` 提交 Pull Request，说明解决的问题、行为变化、验证方式与已知限制。
4. 审核通过后合入。避免将无关重构、环境修复与产品功能混在同一 PR 中。

外部贡献者可以从自己的 Fork 提交 PR，无需访问维护者的其他开发环境。新增代码默认沿用本项目 Apache-2.0 许可；引用第三方代码时保留其来源、版权及许可声明。

## 从实验环境选择公开改动

维护者可能先在实验分支或非公开研发环境中验证功能。公开发布以适合独立使用的成熟提交为单位，不直接把实验环境的全部历史、运行目录或配置推送到公开 `main`。

1. 确认候选提交的功能完整、依赖明确，不包含私人配置或真实数据。
2. 从公开 `main` 创建 `release/<主题>` 分支。
3. 按依赖顺序选择候选提交；可以使用 `git cherry-pick -x <commit>` 保留代码来源。存在冲突时逐项审查，不直接覆盖公开分支。
4. 同时审查最终差异和公开 main 到 release 分支之间的每一个提交，例如 `public/main..release/<主题>`（远程名按实际配置替换）。不能只看最终文件差异：中间提交中的聊天、凭据或私人数据，即使已在后续提交删除，也仍会随历史公开。含有这类内容的历史不得发布；应从干净的公开 main 重新整理可公开提交，再复查完整提交区间。完成代码与文档检查后，在公开分支重新验证测试。
5. 提交面向公开 `main` 的 release PR，描述公开版本实际提供的功能；不需要披露非公开仓库地址、本机路径、访问凭据或私人调试记录。
6. 审核后合并。没有通过验证的实验功能继续保留在实验环境中。

如果一个提交同时包含可公开代码和私人内容，先在独立分支整理成干净、可审查的提交，不依赖提交后的清理来隐藏已有历史。

## 本地验证

按照 [README 的源码运行步骤](../README.md#源码运行)安装指定 Node.js、Python 与项目依赖。在当前 PowerShell 中选择项目 Python：

```powershell
$env:WECHATVIBE_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
npm.cmd run typecheck
npm.cmd run build:advisor-ui
npm.cmd test
```

- 优先使用合成会话与临时目录复现问题。
- 修改前端源文件时，核对生成的界面 bundle 与源码是否一致。
- `npm.cmd test` 汇总类型检查、Node、桌面脚本与 Python 回归；如报告依赖缺失或环境跳过，应如实记录，不能写成已经验证。
- `npm.cmd run test:model` 会实际加载本地 Laya，需先安装模型；它不属于没有模型时的最小检查。
- 合成测试通过不等于已验证所有微信版本、真实账号数据或模型服务商。真实环境测试应单独说明范围，公开报告仅保留脱敏结果。

## 公开内容检查

提交前检查文件与提交历史，尤其注意：

- 不提交聊天数据库、消息正文、联系人资料、头像缓存、分析结果或真实会话截图。
- 不提交 API Key、数据库密钥、身份令牌、认证文件、带凭据的 URL 或个人模型配置。
- 不提交虚拟环境、依赖目录、模型权重、安装包和机器相关的运行目录。
- 演示使用合成数据；错误报告提供最小复现和必要的脱敏日志。
- 保留新增依赖及引用代码的许可证、NOTICE 和来源说明。

`.gitignore` 是第一层过滤，不能替代对最终差异与历史的检查。文档中的示例应使用通用占位值，不依赖维护者个人的目录或账号。

## 产品发布与上游同步

当前提供源码开发版。继承的上游标签用于溯源，不代表 Know Your Friends 已发布同名产品版本。

建立独立安装包发布前，需要明确应用标识、产物命名、更新地址、签名与校验方式，并测试安装、升级、回退及数据保留。完成这些工作前，不把上游更新入口写成 Know Your Friends 的更新能力。

关注 [WechatVibe](https://github.com/tswawa/WechatVibe) 的改进与兼容性修复。引入上游变更时保留来源，评估与当前公开版本的差异，并通过单独 PR 审核。项目来源和上游贡献者署名不因独立维护而移除。

每次公开功能或发布方式变化时，同步更新 README、相关使用文档与 [修改说明](modifications.md)。规划功能应与当前可用功能分开记录。
